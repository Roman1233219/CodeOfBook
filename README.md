# 📖 Code as Book (CoB) Methodology
> **Превращаем разработку ПО из проектирования «заводов-монолитов» в написание живой, читаемой и автономной истории.**

**Code as Book (CoB)** — это децентрализованная архитектурная парадигма, созданная для современных бизнес-приложений. Она заменяет горизонтальное слоение классических архитектур (Clean, Hexagonal) на **вертикальное деление по смыслу**, делая структуру проекта такой же прозрачной, как оглавление книги.

---

## 🚀 I. Философия: Смерть «Архитектурного Налога»

В классических архитектурах логика размазана горизонтально (Data -> Domain -> Presentation). Чтобы добавить одну кнопку, разработчик «протыкает» 5–7 слоев, тратя до 40% времени на обслуживание структуры.

**CoB меняет правила игры:**
*   🏛 **Приложение — это Библиотека.** Проект состоит из независимых Книг (модулей).
*   📘 **Книга — это автономный мир.** У неё есть своя память (Сущности), свои глаза (Экраны) и своя воля (Главы).
*   ✍️ **Читаемость — приоритет №1.** Если сюжет приложения нельзя прочитать как текст, это плохой код.

---

## 📂 II. Анатомия Книги (Оглавление)

Каждая Книга имеет строгую структуру папок, обеспечивающую полную изоляцию и порядок:

### 📚 ВВЕДЕНИЕ (Introduction — Физика Мира)
Фундамент, определяющий возможности мира:
*   **СУЩНОСТИ (Entities):** Память Мира. Описание состояний, которые напрямую связаны с отображением (GlobalState).
*   **ЭКРАНЫ (Screens):** Визуальный ряд. Только декларативный UI (Jetpack Compose), лишенный логики.
*   **ШАБЛОНЫ (Templates):** **Законы Физики.** Сеть (Retrofit/Ktor), Базы данных (Room/Realm), Карты, Железо — всё подключается здесь через интерактивные `.book` шаблоны.

### 📖 ГЛАВЫ (Chapters — Сюжетные линии)
Логический центр принятия решений. В CoB каждая Глава — это **автономный пакет**:
*   **Файл Сюжета (.book):** Режиссерский сценарий. Описывает, *что* происходит в ответ на действия пользователя.
*   **Папка ПРАВИЛА (Rules):** Команда персональных «каскадеров» главы. Здесь лежат технические правила, созданные специально для этого сюжета.

### 📝 ЗАМЕТКИ (Legacy Bridge — Заметки на полях)
**Аварийный выход.** Используется исключительно для связи Книги с «грязным» Legacy-кодом старого приложения, который ещё не переведен на методологию CoB.

---

## 🧠 III. Нервная система: Шина и Письма

Все компоненты общаются исключительно через **Письма (Letters)**, которые доставляет **Шина (PlotBus)**.

| Поле | Описание | Пример |
| :--- | :--- | :--- |
| **ОТПРАВИТЕЛЬ** | Кто породил событие | `BOOK.SCREEN.BUTTON` |
| **ПОЛУЧАТЕЛЬ** | Кому адресовано | `CHAPTER_AUTH` или `RULE_NETWORK` |
| **МЕТОД** | Что произошло | `CLICK`, `SUCCESS`, `ERROR` |
| **ДАННЫЕ** | Параметры события | `Map<String, Any>` |

> **Принцип Traceability:** `ID объекта == Имя Класса == Имя Файла`. Лог Шины становится готовой стенограммой работы приложения, понятной даже бизнесу.

---

## 🎬 IV. Логика Сюжета: Закон Успеха (Happy Path)

Глава — это «Хроника Побед». В ней строго запрещены технические ветвления по ошибкам.

1.  **Каскадные Цепочки:** Глава вызывает **Блок Правил**, выполняющихся последовательно. Если первое правило успешно — запускается второе.
2.  **Слепая Вера:** Глава реагирует только на сигнал `УСПЕХ`. Если цепочка прервалась, Глава просто «замирает», не загромождая сюжет техническим мусором (404, Timeout и т.д.).

---

## ⚙️ V. Физика Действия: Автономия Правила

Правило — это **Ответственный Исполнитель**. Оно берет на себя всю «грязную работу» и риски.

**Архитектурный Контракт Правила:**
*   **ДЕЙСТВИЯ:** Линейный конвейер команд (Установить, Запросить, Сохранить). Правило вызывает операции, определенные в **Шаблонах**.
*   **ОШИБКА (План спасения):** Если любая команда упала, Правило само вызывает **Менеджер Ошибок** и не беспокоит Главу техническими деталями.
*   **УСПЕХ:** Автоматический сигнал Шины для продолжения сюжетной линии.

---

## ⚡ VI. Механизмы исполнения (CoB Engine)

### 1. Short Circuit (Короткий путь данных)
Данные не гоняются через Главу обратно в UI.
*   Правило пишет результат **напрямую в Состояние Экрана** (`GlobalState`).
*   Экран мгновенно перерисовывается. Глава получает лишь короткий отчет: «Готово».

### 2. Интерактивные Шаблоны (Living Templates)
Любая внешняя библиотека (Ktor, Firebase, Realm) описывается как «Живой Шаблон». Это позволяет разработчику менять преобразования данных (`ВХОД/ВЫХОД`) кликом мышки прямо в коде реализации.

### 3. Семантический Менеджер Ошибок (The Safety Net)
Технические сбои маппятся на человеческие имена внутри шаблонов. Менеджер Ошибок решает: отправить пользователя на `ЭКРАН_СЕТИ` или попросить Главу «переиграть» сюжет сначала.

---

## 🎯 Резюме

В методологии **CoB** разработчик перестает быть «механиком» инфраструктуры. Он становится **Автором**.

*   🖋 **Пиши Главу как поэт** (о смыслах и сюжете).
*   ⚖️ **Пиши Правило как юрист** (о данных, рисках и контрактах).
*   📖 **Пусть Книга работает сама.**

**CoB сокращает Time-to-Market в 10 раз, делая поддержку приложения такой же простой, как чтение оглавления любимой книги.**
